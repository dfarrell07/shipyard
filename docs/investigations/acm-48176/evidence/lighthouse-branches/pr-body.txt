The netshoot and nginx-demo helper Deployments hard-code `runAsUser: 10000`. OpenShift's restricted-v2 SCC only admits
UIDs from the namespace's allocated range, so the ReplicaSet controller cannot create the pods. Every service discovery test
that uses them then fails with "Actual pod count 0". Connectivity tests still pass when run as a cluster admin, because they
create pods directly and admission uses the admin's own SCC access.

This leaves `runAsUser` unset when the target cluster serves the `security.openshift.io` API group, so SCC admission assigns a
UID from the namespace range. Elsewhere UID 10000 is kept: older nettest images default to root and would otherwise fail
`runAsNonRoot`. Subctl derives the nettest image from the deployed Submariner version, so this combination happens. The lookup
is per target cluster and goes through `AwaitUntil`, so it retries transient errors within the operation timeout and otherwise
fails the test rather than guessing. It uses a raw `/apis` request because `ServerGroups()` ignores context deadlines. All
other hardening is unchanged.

The new Ginkgo suite in `test/unit/framework` covers both platforms, per-cluster selection, a transient retry, discovery errors,
invalid responses, and the timeout. It lives outside `test/e2e`, which the unit runner skips.
